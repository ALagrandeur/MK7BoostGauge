================================================================
   MK7BoostGauge - PROCEDURE D'INSTALLATION
   Pi Zero 2W + WaveShare 2-CH CAN HAT
================================================================

Repo GitHub : https://github.com/ALagrandeur/MK7BoostGauge
Date : mai 2026


----------------------------------------------------------------
ETAPE 0 - VERIFIER LE MATERIEL RECU
----------------------------------------------------------------

Avant de commencer, verifier que tu as :

[ ] Raspberry Pi Zero 2W
[ ] WaveShare 2-CH CAN HAT (avec 2 modules MCP2515)
[ ] MicroSD 16 Go (ou plus) Class 10
[ ] Adaptateur MicroSD vers USB (pour flasher depuis ton PC)
[ ] Cable USB micro-B (pour alimenter le Pi pendant l'install)
[ ] DC-DC step-down 12V vers 5V USB-C 3A (pour la voiture, plus tard)
[ ] Boitier Pi Zero (optionnel mais recommande)
[ ] 4 vis M2.5 pour fixer le HAT sur le Pi (souvent fournies)


----------------------------------------------------------------
ETAPE 1 - FLASHER LA CARTE MICROSD AVEC DIETPI (sur PC Windows)
----------------------------------------------------------------

OS choisi : DietPi 64-bit pour Raspberry Pi Zero 2W
   Avantages : boot 2x plus rapide, footprint reduit (~400 Mo vs 2 Go),
   logs en RAM = moins d'usure SD, optimise pour SBC.

1. Telecharger l'image DietPi :
   https://dietpi.com/#download
   Choisir : Raspberry Pi -> "ARMv8 64-bit" -> bouton DOWNLOAD
   (fichier 7z, ~150 Mo)

2. Extraire le .img du 7z (utiliser 7-Zip si besoin :
   https://www.7-zip.org/)

3. Telecharger un outil de flash :
   - Raspberry Pi Imager : https://www.raspberrypi.com/software/
     (le plus simple : "USE CUSTOM IMAGE" pour pointer le .img DietPi)
   - OU Balena Etcher : https://etcher.balena.io/

4. Inserer la MicroSD dans le PC (via adaptateur USB).

5. Avec Raspberry Pi Imager :
   - Choose Device       : Raspberry Pi Zero 2 W
   - Choose OS           : "Use custom" -> selectionner le .img DietPi extrait
   - Choose Storage      : ta MicroSD
   - Cliquer NEXT puis "NO" pour ne PAS appliquer les settings OS
     (DietPi a son propre systeme de pre-config)
   - Cliquer YES pour ecrire

6. Attendre la fin du flash (~5 min), MAIS NE PAS EJECTER ENCORE.

7. Pre-configurer DietPi avant le 1er boot :
   Ouvrir l'Explorateur Windows. La carte SD apparait comme "boot".
   Editer 2 fichiers a l'interieur (avec Notepad) :

   FICHIER 1 : "boot/dietpi.txt"
     Trouver et modifier ces lignes :
       AUTO_SETUP_NET_HOSTNAME=boostgauge
       AUTO_SETUP_LOCALE=en_US.UTF-8
       AUTO_SETUP_KEYBOARD_LAYOUT=ca           (ou us, fr, etc)
       AUTO_SETUP_TIMEZONE=America/Toronto     (ton fuseau)
       AUTO_SETUP_NET_WIFI_ENABLED=1
       AUTO_SETUP_NET_WIFI_COUNTRY_CODE=CA
       AUTO_SETUP_AUTOMATED=1
       AUTO_SETUP_GLOBAL_PASSWORD=BoostGauge2026   (pwd que tu choisis)
       SURVEY_OPTED_IN=0
       AUTO_SETUP_SSH_SERVER_INDEX=-2          (=OpenSSH complet, recommande)

   FICHIER 2 : "boot/dietpi-wifi.txt"
     Trouver et remplir (entre les guillemets) :
       aWIFI_SSID[0]='NomDeTonWiFiMaison'
       aWIFI_KEY[0]='MotDePasseWiFiMaison'
       aWIFI_KEYMGR[0]='WPA-PSK'

8. SAUVEGARDER les 2 fichiers, puis ejecter proprement la MicroSD.


----------------------------------------------------------------
ETAPE 2 - ASSEMBLER LE PI + HAT
----------------------------------------------------------------

1. Pi NON branche.

2. IMPORTANT : retirer les 2 jumpers de terminaison 120 Ohms du HAT
   (cherche les marquages "R-CAN0" et "R-CAN1" sur le PCB du HAT)
   - Sur le bench tu peux les laisser pour test
   - Pour la voiture il FAUT les enlever (sinon tu desequilibres le bus)

3. Empiler le HAT sur le Pi par les pins GPIO 40 broches.
   Visser les 4 vis M2.5 pour le fixer.

4. Inserer la MicroSD flashee dans le Pi.

5. Brancher cable USB micro-B sur le port "PWR" du Pi (pas le port USB OTG).
   Le Pi va booter automatiquement.


----------------------------------------------------------------
ETAPE 3 - PREMIER BOOT DIETPI + CONNEXION SSH
----------------------------------------------------------------

DietPi premier boot : ~5 a 15 min (telecharge updates, configure systeme,
                       installe paquets de base). Plus long que Pi OS Lite,
                       MAIS un seul boot, ensuite ~15 sec.

1. Attendre 8-10 minutes apres avoir branche l'alim.
   Le Pi va :
     - Boot initial (1 min)
     - dietpi-update (telecharge derniers packages, 3-5 min)
     - dietpi-software (config initiale, 2-3 min)
     - Reboot automatique (1 min)
     - Pret a SSH

2. Sur ton PC Windows, ouvrir PowerShell ou cmd, taper :

   ssh dietpi@boostgauge.local

   (Si "boostgauge.local" ne marche pas, trouve l'IP du Pi sur la page
    admin de ton routeur et utilise : ssh dietpi@192.168.X.X )

3. Quand demande, taper "yes" pour accepter la cle, puis le mot de passe
   que tu as defini dans dietpi.txt (ex: BoostGauge2026).

4. Tu es maintenant en SSH sur le Pi. Le prompt :
   dietpi@boostgauge:~$

5. NOTE : DietPi est minimaliste, certaines commandes manquent.
   Si tu vois un menu "DietPi-Launcher" au login, presser Ctrl+C
   pour passer en shell normal.


----------------------------------------------------------------
ETAPE 4 - INSTALLER MK7BoostGauge
----------------------------------------------------------------

Coller ces commandes une par une sur le Pi (en SSH) :

   sudo apt update
   sudo apt -y install git

   git clone https://github.com/ALagrandeur/MK7BoostGauge.git
   cd MK7BoostGauge
   sudo bash pi_setup/setup.sh

L'install va prendre 5 a 10 minutes (telecharge dependances Python,
configure les overlays CAN, cree le service systemd).

Le script auto-detecte DietPi vs Pi OS Lite et utilise le bon
utilisateur (dietpi vs pi) automatiquement.

Quand c'est fini, tu vas voir :
   "==> [8/8] Done!"

Faire un reboot :

   sudo reboot

Attendre 30 secondes, puis SSH a nouveau :

   ssh dietpi@boostgauge.local


----------------------------------------------------------------
ETAPE 5 - VERIFIER QUE TOUT FONCTIONNE
----------------------------------------------------------------

Sur le Pi (SSH) :

1. Verifier que les 2 interfaces CAN sont visibles :

   ip -br link show | grep can

   Tu devrais voir :
     can0   UP   <NOARP,UP,LOWER_UP,ECHO>
     can1   UP   <NOARP,UP,LOWER_UP,ECHO>

   Si tu ne vois rien : reboot encore (parfois 2 reboots necessaires).
   Si toujours rien : verifier que le HAT est bien empile et les vis serrees.

2. Verifier que le service tourne :

   systemctl status boostgauge

   Doit afficher : "active (running)" en vert.

3. Voir les logs en temps reel :

   journalctl -u boostgauge -f
   (Ctrl+C pour quitter)


----------------------------------------------------------------
ETAPE 6 - TEST CAN SUR LE BENCH (optionnel mais recommande)
----------------------------------------------------------------

1. Brancher le HAT au cluster sur ton bench (CAN0 ou CAN1) :
     HAT CAN-H -> Cluster CAN-H (pin 17 du connecteur 18-broches cluster)
     HAT CAN-L -> Cluster CAN-L (pin 18)
     Pi GND     -> Cluster GND  (pin 10)

2. Ouvrir le navigateur sur ton PC :
     http://boostgauge.local
     ou
     http://192.168.X.X (l'IP du Pi)

3. Tu devrais voir l'interface MK7BoostGauge avec :
     - Pill "WAITING" en haut (jaune)
     - Cards "Etat live" + "Configuration mapping" + "Modes"

4. Sur le bench, comme il n'y a pas de WBA_03 (gear) envoye, le mode
   restera "WAITING" (pas de TX). C'est normal sans signal levier.

5. Pour tester un envoi force, tu peux temporairement modifier le code
   ou attendre la voiture.


----------------------------------------------------------------
ETAPE 7 - CONFIGURER LE WIFI AP (pour la voiture)
----------------------------------------------------------------

Une fois que tout marche en mode WiFi maison, on bascule en AP autonome :

   sudo bash pi_setup/ap_setup.sh
   sudo reboot

Apres reboot, le Pi cree son propre WiFi :
     SSID     : MK7-BoostGauge
     Password : boostgauge
     IP Pi    : 192.168.4.1

Connecte-toi a ce WiFi avec ton telephone, va sur :
     http://192.168.4.1


----------------------------------------------------------------
ETAPE 8 - INSTALLATION DANS LA VOITURE
----------------------------------------------------------------

PRE-REQUIS : avoir le Y-cable extension gateway en main, identifier
les bonnes paires CAN (Cluster + PCM) avec multimetre :
   - Resistance ~60 Ohms entre H et L = c'est une paire CAN active

Cablage (assignation OFFICIELLE) :

   +12V auto (ignition switched, fusible 2A) -> DC-DC IN+
   GND chassis voiture                       -> DC-DC IN-

   DC-DC OUT (5V USB-C)                      -> Pi USB-C PWR

   HAT CAN0 H/L  -> Y-cable Cluster CAN-H/L      (TOUJOURS cluster)
   HAT CAN1 H/L  -> Y-cable PCM CAN-H/L          (mode normal)
                    OU
                    Port OBD-II pin 6 / pin 14   (mode diagnostique)

LE TOGGLE CAN1 :

Dans l'interface web, section "CAN - branchement", tu peux basculer
CAN1 entre 2 modes sans rebooter :

   - CAN1 -> PCM         : tap direct Powertrain via Y-cable.
                            Mode rapide (sniff broadcasts).
                            A utiliser pour install permanente.

   - CAN1 -> Diagnostic  : connexion port OBD-II J1962 (pinout standard).
                            Pin 6  = CAN-H
                            Pin 14 = CAN-L
                            Mode UDS query forcee (gateway filtre les
                            broadcasts vers le port OBD).
                            A utiliser pour debug / acces temporaire
                            sans demonter le tableau de bord.

Pour basculer :
   1. Debrancher la prise CAN1 du Y-cable (ou du OBD-II)
   2. Brancher sur l'autre source physique
   3. Dans l'UI web -> cocher le bon mode (PCM ou Diagnostic)
   4. Sauvegarder

ATTENTION : NE JAMAIS brancher sur batterie permanente (le Pi va
            decharger la batterie en 2-3 jours). TOUJOURS sur fusible
            qui se coupe avec le contact.


----------------------------------------------------------------
ETAPE 8.5 - SAFETY : MODE LISTEN-ONLY (RECOMMANDE 1ER ESSAI)
----------------------------------------------------------------

Avant de demarrer le moteur pour la 1ere fois avec le device branche,
RECOMMANDATION FORTE :

1. Dans l'UI web -> section "Securite"
2. ACTIVER la case "CAN1 LISTEN-ONLY"
3. Sauvegarder

Ca garantit que :
   - AUCUNE frame ne sera envoyee sur le bus CAN1 (PCM ou Diagnostic)
   - Aucune UDS query ne partira
   - Le mode est 100% passif sur CAN1
   - Le bus Cluster (CAN0) reste actif (sinon pas de gauge boost)

Ainsi tu peux :
   - Verifier que le pinout du Y-cable est correct (rien envoye = rien casse)
   - Voir les frames qui ARRIVENT sur CAN1 (compteur RX qui monte)
   - Eliminer tout doute sur le branchement physique

Quand tout est confirme bon, DESARMER LISTEN-ONLY pour activer la
fonction MAP (UDS query ou sniff selon mode CAN1).

ATTENTION : la blocklist AIRBAG (0x040, 0x572, 0x585) est TOUJOURS active,
            independemment de listen-only. C'est hardcode dans le firmware,
            impossible a desactiver via l'UI ou la config.


----------------------------------------------------------------
ETAPE 9 - PREMIER ESSAI VOITURE
----------------------------------------------------------------

1. Mettre le contact (cle ON, sans demarrer)
2. Attendre 30-45 secondes (boot du Pi)
3. Sur ton telephone, connexion au WiFi "MK7-BoostGauge"
4. Ouvrir http://192.168.4.1
5. La pill devrait passer de "WAITING" a "TEMP" (levier en P)
6. Demarrer le moteur
7. Bouger le levier en S -> pill passe a "BOOST", l'aiguille suit la MAP

Si ca ne marche pas, en SSH (depuis ton telephone via app Termux ou
ton PC en se connectant au WiFi de la voiture) :

   journalctl -u boostgauge -n 50

Pour voir les 50 dernieres lignes de log.


----------------------------------------------------------------
ETAPE 10 - CALIBRATION
----------------------------------------------------------------

Dans l'interface web, ajuster les sliders :

   MAP min (mbar)    : valeur MAP a vide moteur tournant idle (~300)
   MAP max (mbar)    : valeur MAP a fond boost (~2500 sur Alltrack)
   Temp min (C)      : 50 (aiguille en bas)
   Temp max (C)      : 130 (aiguille dans le rouge)
   Scale             : 1.0 (laisser, ajuster si non lineaire)
   Offset (C)        : 0  (laisser sauf si decalage visible)
   TX rate (Hz)      : 25 (monter a 35-40 si flicker visible)

Cliquer "Sauvegarder" - la config persiste apres reboot.

COMMANDES UTILES
----------------------------------------------------------------

Voir les logs en direct :
   journalctl -u boostgauge -f

Redemarrer le service (sans rebooter le Pi) :
   sudo systemctl restart boostgauge

Mettre a jour le code depuis GitHub :
   cd ~/MK7BoostGauge
   git pull
   sudo systemctl restart boostgauge

Voir les frames CAN en direct sur le bus Cluster (CAN0) :
   candump can0

Voir les frames CAN en direct sur le bus PCM/Diagnostic (CAN1) :
   candump can1

Envoyer une frame de test sur Cluster :
   cansend can0 647#80FDFF7F000000C1

Editer la config a la main :
   sudo nano /var/lib/boostgauge/config.json
   sudo systemctl restart boostgauge

EN CAS DE PROBLEME
----------------------------------------------------------------

Probleme : "ssh: Could not resolve hostname boostgauge.local"
Solution : trouve l'IP du Pi via le routeur, utilise l'IP
           Avec DietPi, utiliser : ssh dietpi@<IP>
           Avec Pi OS,   utiliser : ssh pi@<IP>

Probleme : "ip link" ne montre pas can0/can1
Solution : verifier le fichier config.txt contient bien les overlays
              DietPi  -> /boot/config.txt
              Pi OS   -> /boot/firmware/config.txt
           Ces lignes doivent etre presentes :
              dtparam=spi=on
              dtoverlay=mcp2515-can0,oscillator=12000000,interrupt=25
              dtoverlay=mcp2515-can1,oscillator=12000000,interrupt=24
           Si manquant, relancer : sudo bash pi_setup/setup.sh
           puis : sudo reboot

Probleme : DietPi premier boot bloque ou n'avance pas
Solution : patience, le 1er boot prend 8-15 min sur Pi Zero 2W.
           Si vraiment bloque (>20 min), debrancher / rebrancher.
           Re-verifier /boot/dietpi-wifi.txt (SSID + password corrects).

Probleme : DietPi - "sudo apt update" ne marche pas
Solution : sudo dietpi-update          (mettre a jour DietPi d'abord)
           puis : sudo apt update

Probleme : Service crash au boot (status "failed")
Solution : voir les logs : journalctl -u boostgauge -n 100
           probable : python-can manque, refaire pip install dans venv

Probleme : Pas de reponse du cluster (aiguille ne bouge pas)
Solution : verifier candump can1 - tu dois voir l'ID 0x394 arriver
           si vide, le cable cluster est mal branche
           si 0x394 arrive mais aiguille bouge pas, verifier
           que tu envoies bien Motor_09 (0x647) en mode S/M/N

Probleme : Aiguille flicker trop
Solution : monter TX rate Hz a 35 ou 40 dans l'interface web

Probleme : SD card corrompue apres coupure brutale
Solution : reflasher la SD, puis activer overlayfs read-only
           (script a venir, demande-moi quand pret)
